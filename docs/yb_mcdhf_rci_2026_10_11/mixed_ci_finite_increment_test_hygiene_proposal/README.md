This is a source-only proposal after [guard003 completed](../mixed_ci_finite_increment_guard_qualification003/RESULTS.md). The mutable shared test has not been edited. No H / CI / gradient / radial increment / optimizer or thirteen-point rerun is authorized here.

Its [archive identity](../mixed_ci_finite_increment_implementation/test_source_archive/045ee541fc648ea9bbc51a476d04fe2a3bf31b0158bfcc02c9daa8357ab2caa8/archive_identity.json) binds the original repo path, original candidate/source epoch, failed result and qualification contract. The source remains exactly the originally executed test; none of its gates or evidence is relabelled.

The proposed new shared test changes exactly three statements: outside the explicit resource driver `finite_problem` uses `pytest.skip` instead of `pytest.fail`; the directional derivative chooses saved points at indices `3+6d` and `4+6d` (`±1e-6`) instead of `1+6d` and `2+6d` (`±1e-4`); the denominator changes from `2e-4` to `2e-6`. Relative `1e-5` / absolute `1e-8` gates, all thirteen generated points, oracle comparisons, unsupported guards, physical code and call limits remain unchanged. The [candidate bytes](candidate_test_mixed_ci_finite_increment.py) are a proposal artifact, not an executable test at their current docs path; their original `REPO=__file__.parents[1]` assumption applies after the exact approved bytes are installed at the shared test path.

The change prevents unsealed ordinary test panels from accidentally constructing the resource-only physical fixture. Pure-array response tests can run normally; live physical cases skip. A future explicitly sealed physical qualification must bind the new test SHA and its own driver/contract. Old sealed drivers must not silently execute the new test. No old output is regenerated or changed.

There are two distinct verification modes after this transition:

1. **Current working-tree identity** remains strict. An old verifier that demands the current `tests/test_mixed_ci_finite_increment.py` equal `045ee…` must correctly report a different current test epoch after the approved edit. It must not be run and called a historical failure or overwritten with a new “pass.”
2. **Historical content identity / replay** resolves only the exact original test path + exact old SHA to the declared immutable archive. [The resolver](historical_test_identity.py) validates that archive, returns the original bytes and retains both the original logical path and the physical archive path. All other paths and SHA gates remain unchanged. This is an explicit new replay-resolution manifest, not a rewrite of old scientific contracts.

For executable historical source/metadata replay, materialize those exact old bytes at `tests/test_mixed_ci_finite_increment.py` inside an isolated epoch root and keep the original repo-relative directory structure. Copy the exact frozen 356-file candidate source (and original frozen 354 comparator), original bound scripts/contracts and saved assets from their existing archives into that root. Files whose `Path(__file__).resolve()` establishes the epoch root must be real copies, not symlinks back to the new working tree. Before and after verification, compare every bound byte using the original expected hashes. The old mutable working tree is never temporarily overwritten. The archived test path itself is not directly executable because its original `REPO` calculation would point to the wrong directory.

The [binding inventory](historical_binding_inventory.json) identifies 28 current documents, contracts, scripts and proofs referring to the old shared path. Each keeps its original bytes and status. Original failed finite qualification, guard002 failure, zero-builder audit and guard003 success remain separate epochs. The resolver may be used by a *new* explicitly labelled historical metadata consumer; it cannot retroactively change the original direct-path verifier or permit a physics rerun.

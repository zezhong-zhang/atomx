`_block_structure` allocates pattern layouts, determinant integers, slices and spinor labels, then retains the complete `BlockStructure` in a 32-entry LRU. Its largest expanded coordinate count is bounded by 7,070,281. Python dictionaries, lists, tuples, integer/set capacity and allocator overhead are not included in the dense-array totals.

`_coefficient_table` retains Python `rows/cols/data/pairs`, key objects and normal-ordered field caches while creating the CSR table and int64 pair coordinates. With p connected entries, coordinates consume 16p bytes; CSR coefficient storage is bounded by 16z+8(p+1) bytes for z nonzeros under a conservative int64-index representation, before Python construction lists and conversion temporaries. The numerical determinant CSR consumes at most 16p+8(D+1) bytes. These equations are source bounds, not measured p/z. Sparse signed projections, highest-weight states, pattern layouts and `_verify_cached` also remain resident through their separate LRUs.

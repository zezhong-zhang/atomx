# Evidence-only native contribution ledger, version 1

This ledger contains **eight whole records: seven finite physics/operator pairs and one optimization-trajectory aggregate**. Six pairs are eligible as numerically qualified, scope-limited historical measurements. They form only **three distinct orbital-point groups, an upper bound on independent examples**. Every eligible physics class and exact comparable context currently has only one group. These groups are not certified IID samples. The data cannot establish learned uncertainty, AI acceleration, or transferable corrections to current31.

The catalog is explicit and includes worsening outcomes. Rank expansion at accepted160 increases all four transition energies, and screened s/d/p virtuals worsen the reported overall gaps. Their signed contributions remain in the ledger. Neither NIST agreement nor improvement determines inclusion or eligibility.

The four fixed160 channels share the exact same original orbital-point archive and are one group. The two f-seed experiments share literal208 and are one group. The inner-order operator experiment uses the separately bound recovered29 point. The optimization aggregate is a separate family: its 17 checkpoints do not add 17 physics examples. The group-held-out evaluation unit is `independent_group_id`, not spectral line, state, endpoint, or checkpoint. No splitting or learned fitting occurs in this builder.

Each row carries before/after source maps, nuclear workspace binding, native radial representation, frozen point and owner/archive identities, ordered physical UIDs, complete consumer CI-space counts, signed absolute lower/upper shifts, the four-line vector, degeneracy-weighted centroid/splitting deltas, original failed gates, stationarity status, measurement cost scope, and exact JSON provenance. Historical native owner/H/CI snapshots are referenced by archived JSON/header/array SHA declarations; numerical arrays are never opened or rehashed. Complete source JSON owner headers remain archived, while the dataset stores compact summaries and their full-header hashes.

`predictor_features` contains only six pre-outcome native fields: `ion_Z`, `electron_count`, `n_radial_before`, `n_radial_after`, `n_target_CSF_before`, and `n_target_CSF_after`. Here CI count means the complete matrix dimension actually retained by that consumer: the static531 experiment retains all 16 blocks, whereas rank/virtual records retain complete selected target sectors. No count is inferred from NIST, an observed shift, runtime, or improved agreement. Missing native counts remain null and make the row predictor-ineligible.

`comparable_context` binds source map, declared nucleus plus native workspace SHA, retained operator, native radial representation, and `ordered_state_UIDs`. Intentional operator-source changes are recorded as before/after source maps; the Gauss-order expectation experiment has its own physics class. Different points are separate groups, and categorical/context compatibility is mandatory before any advisory selector could use a historical row. No row certifies transfer to current31. Descriptive nuclear text is retained verbatim; the ledger does not silently normalize different source contracts into an equivalent nuclear model.

NIST values, uncertainties and nominal gaps appear only in `validation_only`; they never enter the predictor block or target selection. Missing uncertainty stays null. The operator-only Gauss-order experiment did not measure stationarity: its `before` status stays null, and absolute before/after eigenenergies stay null. Its five absolute operator-expectation shifts are available and retained, but are not relabeled as new eigenenergies. Numerically qualified fixed-orbital records may be eligible with inherited stationarity=false; eligibility is not production, full-correlation or experimental certification.

The loader permits only explicit repository-local `.json` references with exact expected hashes. It never follows the NPZ, source archive or other dependency paths embedded in those JSON files. Unsupported schemas, changed hashes, missing/ambiguous physical UIDs, unmatched energy references and unbound proofs reject or mark evidence unsuitable. All actual consumed input hashes were checked again after the build. The existing [pure iteration planner](../../atomx_hourly_progress_2026_10_10/iteration_planner.py) supplied the design precedent—explicit capabilities, identity and retained failures—but its array-reading collector and dispatcher were not called. This module provides data, not execution.

The actual metadata run closed with 17 standard-library synthetic schema/invariant/provenance/leakage tests PASS and all three commands exit0. Tests cover signed upper-minus-lower/centroid/splitting algebra, target-order invariance, UID/root rejection, NIST mutation isolation, missing owner/nucleus/count rejection, source/point mismatches, failed proofs/receipts, group leakage, corrupt JSON hashes, non-JSON/escaping paths and resource admission before reading. These fixtures test dataset mechanics; they do not qualify atomic physics or a learned selector. Full stdout/stderr and command/exit/hash records are in [actual](actual/result.json).

The prospective metadata-only bounds were CPU31, one thread, hard 1 GiB address space and 60 s whole foreground wall allowance. The actual 43 JSON files totaled **33,296,799 raw bytes**; this is not decoded resident memory. The final explicit JSON I/O cap is 64 MiB, with a 64-file cap. The complete metadata pipeline took 0.430 s under uncontrolled conditions; this is not a speedup claim. It made zero NPZ reads/hashes, numerical imports, scientific calls or learned predictions. Exact source/manifest/input hashes and full logs are in the receipt.

Two earlier metadata failures are preserved. [Attempt001](failed_attempt001/actual/manifest.stderr) stopped before tests/building on an incorrect legacy `fixed` versus `fixed_conditions` lookup. [Attempt002](failed_attempt002/actual/builder.stderr) passed the 17 tests but stopped at the original 16 MiB JSON cap. The manifest's integer size census showed the complete owner/embedded checkpoint headers require 33,296,799 bytes, so the successor explicitly raised only JSON I/O to 64 MiB; the 1 GiB AS limit and all physical identities/eligibility rules remained unchanged. No record, owner, state, failed gate or physical model was pruned to make it fit.
